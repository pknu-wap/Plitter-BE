# 캐릭터 생성 V2 운영 적용 절차

## 현재 적용 상태

- 로컬 소스 컴파일 및 관련 JUnit 테스트 39개가 통과했다.
- 운영 서버의 실행 서비스·JAR 경로·배포 명령은 아직 확인하지 못했다.
- 이번 실행 환경에서 운영 SSH 연결이 차단되어 스키마 변경·배포·재시작을 실행하지 않았다.
- 이 문서는 운영 적용 완료 기록이 아니라, 접근 가능한 환경에서 수행할 배포 절차다.

## 적용 순서

1. 현재 서비스의 실행 방식(systemd, Docker 또는 직접 Java 실행), 소스·JAR·외부 설정 경로와 현재 배포 커밋을 확인한다. 기존 배포 방식을 사용한다.
2. DB 연결 대상이 실제 앱 테이블을 가진 DB인지 확인한다. 이번 대화의 조회 결과에서는 `postgres`에 `characters`, `track_features` 등이 존재했다. DB 인스턴스 이름과 DB 이름을 혼동하지 않는다.
3. 현행 아티팩트와 실행 옵션을 복구 가능하게 보존한다. 비밀 설정은 저장소나 PR에 포함하지 않는다.
4. `docs/sql/character_generation_v2.sql`의 nullable JSONB 컬럼 두 개를 먼저 추가한다. 기존 컬럼이나 행은 삭제하지 않는다. 운영에서는 적절한 lock timeout을 설정하고, 잠금 대기가 발생하면 원인을 확인한 뒤 다시 시도한다.
5. 아래 조회로 컬럼의 존재와 타입을 확인한다.

```sql
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'characters'
  AND column_name IN ('generation_spec_json', 'result_metadata_json')
ORDER BY column_name;
```

6. PR의 정확한 커밋으로 기존 빌드·배포 절차를 실행한다. 운영 애플리케이션의 외부 비밀 설정과 DB 접속 정보를 유지한다. 로컬의 오래된 비밀 설정 파일을 복사하지 않는다.
7. 처음에는 `character.generation.v2-enabled=false`로 기동해 기존 캐릭터 상세·다운로드 조회와 소유자 검사를 확인한다.
8. 동일 릴리스에서 해당 값을 true로 전환해 V2 생성을 활성화한다. 설정 전달·재시작 방식은 확인한 기존 런타임을 따른다.
9. 운영 데이터를 검증할 수 있는 소유자의 테스트 플레이리스트에서 생성 요청을 실행한다. 이미지 생성 비용이 발생하며, 본인 소유 데이터와 테스트 용도를 확인한 뒤 수행한다.
10. 이미지 URL의 실제 표시, 이름·태그 3개, 생성·상세·다운로드 응답의 동일성, 저장된 두 JSONB 값을 확인한다. 재생성 시 버전 증가와 최근 조합 회피도 확인한다.

## 복구

- 새 생성에 문제가 있으면 해당 릴리스의 `character.generation.v2-enabled=false`로 전환한다.
- V2 저장 메타데이터를 읽는 코드는 유지한다. 과거 바이너리로 전체 롤백하면 새 캐릭터의 표시 동작이 달라질 수 있다.
- 이미 추가한 nullable 컬럼과 생성 데이터를 즉시 삭제하지 않는다.
- 이미지 생성·업로드 실패와 앱 기동·DB 스키마 오류를 구분해 기록한다.

## 완료 기록에 남길 항목

- PR 번호와 실제 배포 커밋 SHA.
- 런타임·서비스 식별 정보와 배포 시각.
- JSONB 컬럼 확인 결과.
- 활성화한 생성 규칙 버전.
- 생성·상세·다운로드 및 이미지 표시 검증 결과.

확인되지 않은 배포 상태를 완료로 기록하지 않는다.
